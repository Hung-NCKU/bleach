# 《鬼道訓練班》製作流程（教學研究用）

本文完整記錄《鬼道訓練班》從需求到可玩版本的製作過程：系統架構、各模組的實作方法、遇到的問題與解法，以及驗證方式。目標是讓讀者能理解並重現「以語音詠唱施放技能的 3D 對戰遊戲」的關鍵技術。

> 本專案的程式碼由 AI 程式助理（Claude Code）依使用者的需求逐步撰寫與修正完成；本文同時記錄了需求如何在迭代中演變，可作為「人機協作開發遊戲」的研究案例。

## 1. 專案概述

| 項目 | 內容 |
|---|---|
| 類型 | 3D 一對一對戰格鬥（仿《火影忍者 終極風暴》的操作與鏡頭） |
| 核心玩法 | 控制器只能做基本動作；**技能（鬼道）只能用語音詠唱施放** |
| 威力計算 | 依「相似度」與「完整度」決定；只喊招式名＝詠唱破棄（威力 ×0.1） |
| 引擎 | Unity 2022.3 LTS（內建渲染管線） |
| 美術資源 | **零外部美術素材**：角色、場景、特效、音效、UI 全部由程式生成 |
| 語音辨識 | Vosk 離線辨識＋中文小型模型；以拼音做模糊比對 |
| 角色 | 黑崎一護、朽木露琪亞（只有能力值差異） |
| 鬼道 | 收錄中文維基百科「鬼道」條目全部 53 招＋測試用 1 招 |

## 2. 開發歷程：需求與技術方案的演變

開發過程中需求多次調整。下表整理每次變更的原因與技術決策，這些「為什麼改」往往比最終程式碼更有參考價值。

| 階段 | 需求／問題 | 決策 |
|---|---|---|
| 1 | 做一款同類型遊戲，技能以語音詠唱施放，相似度越高或越大聲傷害越高 | 先以網頁（Three.js＋Web Speech API）快速原型 |
| 2 | 使用者要求「不要網頁，使用遊戲引擎」 | 改用 **Unity**。選擇理由：Windows 上有內建聽寫 API，且 C# 生態成熟 |
| 3 | 角色限定一護與露琪亞；**只能用鬼道當技能**；不要卍解、不要專屬技 | 角色只保留能力值差異，所有技能資料化 |
| 4 | 指定鬼道清單與詠唱文，之後要求收錄維基百科全部鬼道 | 鬼道改為**資料驅動**＋**特效原型**（見 5.7） |
| 5 | Windows 內建聽寫（DictationRecognizer）**完全辨識不到** | 改用 **Vosk 離線辨識**，不依賴系統語音設定 |
| 6 | Vosk 能聽到，但同音字導致分數偏低（45–71%） | 比對改為**拼音軟性比對**，提升到 83–100%（見 6） |
| 7 | 先做「按住說話」驗證 → 確認可用後改為「持續監聽」 | 同一套辨識引擎，只改觸發與結算邏輯 |
| 8 | 取消音量計分，加入「完整度」，詠唱破棄改 ×0.1 | 評分改為 相似度 × 完整度 |
| 9 | 畫面「像 20 年前的遊戲」 | 加入後製（泛光、調色、暗角）、魂魄覺醒風格 HUD、3D 頭像 |
| 10 | 倒地後一直被追打 | 倒地全程無敵、倒地 5 秒、起身 1 秒無敵；AI 不追打倒地者 |

**教學重點**：先用最低成本驗證最不確定的部分（語音辨識是否可用），再投入美術與內容。本專案在第 5～7 階段才真正確定語音方案，若一開始就大量投入特效，會面臨重做風險。

| 檔案 | 責任 |
|---|---|
| `GameManager.cs` | 進入點、畫面狀態機、IMGUI、HUD、詠唱評分特效 |
| `Battle.cs` | 一場戰鬥的世界：兩位角色、效果清單、判定、屏障、封印、反鬼相殺、雙重詠唱 |
| `Fighter.cs` | 角色狀態機：移動、連段、防禦、靈壓、受擊、倒地、增益 |
| `FighterModel.cs` / `FaceTex.cs` | 程序化角色模型、姿勢表、動畫風臉部貼圖 |
| `KidoEffects.cs` / `KidoEffects2.cs` | 所有鬼道的特效與判定 |
| `VoiceCaster.cs` | Vosk 引擎（背景執行緒）、持續監聽、發動時機、評分 |
| `Similarity.cs` | 文字正規化、拼音表、軟性 LCS |
| `Spells.cs` | 鬼道資料表與角色能力值 |
| `AIController.cs` | 電腦對手 |
| `Arena.cs` | 瀞靈廷／虛圈場景 |
| `PostFX.cs` / `HudArt.cs` / `Portraits.cs` | 後製、HUD 貼圖、3D 頭像 |
| `CameraRig.cs` / `Particles.cs` / `Sfx.cs` / `MeshGen.cs` / `Mats.cs` | 鏡頭、粒子、合成音效、網格、材質 |

**設計原則**

1. **純程式生成**：沒有任何 Prefab、場景或美術檔，降低協作門檻，也方便 AI 助理在沒有 Unity 編輯器的環境下撰寫。
2. **資料驅動**：鬼道、角色都是資料表，新增招式不需改動戰鬥核心。
3. **玩家與 AI 共用介面**：兩者都輸出同一個 `Intent`（移動、攻擊、跳躍、集氣、防禦），戰鬥邏輯不分敵我。

### 4.1 不開 Unity 也能編譯檢查

開發機上沒有安裝 Unity，因此建立一個只用來編譯的 `.csproj`，把 `Assets/Scripts/*.cs` 全部納入：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>netstandard2.1</TargetFramework>
    <LangVersion>9.0</LangVersion>
    <DefineConstants>UNITY_EDITOR_WIN;UNITY_STANDALONE_WIN</DefineConstants>
    <EnableDefaultCompileItems>false</EnableDefaultCompileItems>
  </PropertyGroup>
  <ItemGroup>
    <Compile Include="..\Assets\Scripts\**\*.cs" />
    <PackageReference Include="UnityEngine.Modules" Version="2021.3.33" />
    <Reference Include="Vosk"><HintPath>..\Assets\Plugins\Vosk\Vosk.dll</HintPath></Reference>
  </ItemGroup>
</Project>
```

每次修改後執行 `dotnet build`，可以在幾秒內抓到型別、API 名稱錯誤（例如曾抓到 `ParticleSystemScalingMode.World` 不存在）。**限制**：Shader 與執行期行為（畫面、物理）無法用這種方式驗證，仍需在 Unity 中實測。

## 5. 逐步製作流程

### 5.1 無場景自動啟動

一般 Unity 專案需要在編輯器裡擺放物件。本專案改用 `RuntimeInitializeOnLoadMethod`，**在任何場景按下 Play 都會自動建立整個遊戲**：

```csharp
public static class Bootstrap
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
    static void Boot()
    {
        if (Object.FindObjectOfType<GameManager>() == null)
            new GameObject("KidoTrainingClass").AddComponent<GameManager>();
    }
}
```

`GameManager.Awake()` 會刪除場景預設的鏡頭與燈光，接著依序建立材質、音效、鏡頭（含後製）、場景、語音引擎。

**注意**：專案資料夾需含 `ProjectSettings/ProjectSettings.asset`，Unity Hub 才會辨識為專案；並把 `activeInputHandler` 設為 0（舊版 Input Manager），否則 `UnityEngine.Input` 會丟例外。

### 5.2 渲染：自製卡通 Shader 與後製

所有 Shader 放在 `Assets/Resources/Shaders/`，以 `Resources.Load<Shader>()` 載入，確保打包時不被剔除。

#### Kido/Toon（角色與場景）

三個 Pass：

1. **描邊（反向外殼法）**：沿世界法線把頂點外推、只畫背面。外推量隨距離放大，讓遠處線寬一致：
   ```hlsl
   float dist = distance(wp, _WorldSpaceCameraPos);
   wp += wn * _Outline * clamp(dist / 8.0, 0.6, 2.0);
   ```
2. **主光源（ForwardBase）**：動畫風的二階明暗，陰影帶顏色（例如皮膚陰影偏粉紅），再加上**髮絲高光帶**與**邊緣光**：
   ```hlsl
   float lit = smoothstep(_ShadeStep - 0.04, _ShadeStep + 0.04, ndl) * smoothstep(0.3, 0.6, shadowAtten);
   float3 c = lerp(albedo * _ShadeColor * ..., albedo * light, lit);
   float band = smoothstep(0.86, 0.9, dot(n, h)) * (1 - smoothstep(0.97, 0.995, dot(n, h)));  // 髮絲光環
   ```
3. **點光源（ForwardAdd）**：讓鬼道發光照亮角色。

#### Kido/Glow、Kido/Alpha、Kido/Sky

- Glow：加算混合（`Blend SrcAlpha One`），用於火焰、雷光、粒子；吃頂點色，所以 LineRenderer 與粒子系統可直接上色。
- Alpha：一般半透明（煙、黑棺、臉部貼花）。
- Sky：三色漸層天空盒。

#### 後製（PostFX＋Kido/Post）

內建管線沒有官方後製時，可用 `OnRenderImage` 自己做：

1. **擷取亮部**（柔性門檻 Soft Knee）→ 降採樣
2. **高斯模糊**（9 tap，水平＋垂直，兩輪）
3. **合成**：原圖＋泛光 → 曝光 → 冷暗部／暖亮部的色調分離 → 飽和度、對比 → ACES 色調映射 → 暗角

這一步對「精緻感」的提升最明顯，成本只有一個 Shader 與 60 行 C#。

### 5.3 程序化建模

#### 自動判斷繞序的網格建構器

Unity 以**順時針**為正面，手算繞序很容易錯（本專案早期就因此修正過擠出網格）。解法是建構器在加三角形時提供「外側方向」提示，自動翻轉：

```csharp
public void Tri(int a, int b, int c, Vector3 hint)
{
    var n = Vector3.Cross(V[b] - V[a], V[c] - V[a]);
    if (Vector3.Dot(n, hint) < 0) { int x = b; b = c; c = x; }
    T.Add(a); T.Add(b); T.Add(c);
}
```

#### 基本形狀（MeshGen）

| 函式 | 用途 |
|---|---|
| `Lathe(ys, rs, seg, depth)` | 車床旋轉體：軀幹、袖子、袴、刀柄、刀鞘（depth 讓截面成橢圓） |
| `Strand(p0, p1, p2, r0, flat, up)` | 沿二次貝茲曲線、截面扁平且漸細的髮束 |
| `SphereGrid(..., deform)` | 可局部、可變形的經緯球面：頭型、臉部貼花、髮帽、沙丘 |
| `Blade(spine, edge, thick)` | 刀背厚、刃口薄的刀身（可彎曲，用於打刀） |
| `Ribbon(...)` | 雙面緞帶：衣領、斬月布條、止繃的白布 |
| `Lines(...)` | 線段網格：天挺空羅的靈壓網、伏火的陷阱線 |

#### 角色組裝（FighterModel）

以關節樹組成，比例約 6 頭身：

```
root ─ body ─ hips ─┬─ torso ─┬─ head（頭、臉部貼花、頭髮）
                    │         ├─ armL ─ fore ─ hand
                    │         └─ armR ─ fore ─ hand ─ sword
                    ├─ legL ─ shin
                    └─ legR ─ shin
```

- **頭型**：球面套用變形函式，下半部往下巴收窄、拉長，形成動畫臉型；臉部貼花使用**同一個變形函式**，保證貼合。
- **交疊衣領**：在軀幹的車床輪廓上取表面點，沿 V 字路徑產生白色緞帶（左襟在上），中間補一塊胸口皮膚曲面。
- **頭髮**：一護是多層刺髮（頭頂、中段、後腦、側邊、瀏海各一組參數）；露琪亞是沿頭型向下的扁平髮束（鮑伯頭），加上眉心那一撮。
- **斬魄刀**：斬月為無護手的菜刀形刀身＋白布纏柄＋垂落布條；袖白雪（封印狀態）為弧形打刀、圓形刀鐔，腰間掛刀鞘。

#### 臉部貼圖（FaceTex）

在 512×512 的畫布上以「有號距離函式＋抗鋸齒」繪製五官：眼白 → 虹膜（上深下淺）→ 瞳孔 → 上眼瞼陰影 → 高光 → 粗睫毛線（二次曲線，粗細漸變）→ 下眼線 → 眉毛 → 鼻子 → 嘴巴。兩個角色只差參數：一護眼睛細長、眉頭下壓（招牌皺眉）；露琪亞眼睛大而圓、紫色虹膜、淡腮紅。

### 5.4 姿勢動畫

沒有使用骨架動畫檔，而是**姿勢表＋插值**：

- 每個姿勢是 11 個關節的歐拉角；每幀以 `Quaternion.Slerp` 逼近目標姿勢。
- 連段攻擊以「出招前（A）→ 揮斬後（B）」兩個姿勢，依攻擊判定時間插值。
- 跑步以正弦波即時產生腿、手擺動。
- 倒地時整個角色根節點後仰 90 度。

### 5.5 戰鬥系統

#### 狀態機

`Idle / Run / Air / Guard / Charge / Dash / Attack / AirAttack / Cast / Chant / Hit / Launched / Down / Bound / Warp / Dead`

#### 終極風暴式操作

| 動作 | 實作 |
|---|---|
| 四段連擊 | 攻擊中再按攻擊會排入下一段；第四段擊飛 |
| 瞬步 | 按靈壓後 0.3 秒內按跳躍 → 消耗靈壓 12，高速衝向對手 |
| 集中靈壓 | 長按靈壓（在按下後 0.3 秒內沒接其他鍵才算長按） |
| 防禦 | 正面受擊減傷，耐久歸零則防禦崩潰 |

#### 受擊與倒地

- 一般攻擊：短暫硬直＋擊退；重擊或擊飛：進入 `Launched`，落地後 `Down`。
- **倒地 5 秒、全程無敵，起身後再 1 秒無敵**（避免被追打）。AI 也會在對手倒地時改去集中靈壓。

#### 靈壓（仿查克拉）

瞬步與所有鬼道都消耗靈壓；長按集中回復，近戰命中與受擊少量回復；奧義需要全滿。

### 5.6 終極風暴式鏡頭

鏡頭永遠在「兩人連線的側面」，追蹤中點，距離隨兩人間距縮放，並稍微偏向玩家背後：

```csharp
var perp = new Vector3(-axis.z, 0, axis.x);           // 連線的垂直方向
float d = Mathf.Clamp(6.5f + dist * 0.75f, 7.5f, 22f);
var want = mid + perp * side * d - axis * (d * 0.28f) + Vector3.up * (...);
```

`side` 在鏡頭繞到另一側太多時才翻轉，避免左右亂跳；玩家永遠在畫面左側。

### 5.7 鬼道系統（資料驅動＋特效原型）

#### 資料表

每個鬼道一筆資料：名稱、**詠唱文**、**招式名**、靈壓消耗、基礎傷害、束縛秒數、持續秒數、特效類型。詠唱文取自維基百科；「不明」者留空，只需喊招式名。

#### 特效原型

53 招若各寫一個類別難以維護，因此先歸納成**原型**，再以參數區分：

| 原型 | 判定方式 | 使用的鬼道 |
|---|---|---|
| 投射物 | 飛行碰撞＋爆炸範圍 | 赤火砲、蒼火墜、雙蓮蒼火墜、雷吼炮、黃火閃、廢炎、金剛爆 |
| 光束 | 線段距離（瞬間／持續多段） | 白雷、牙氣烈光、飛龍擊賊震天雷炮 |
| 位置鎖定 | 施放時鎖定位置，延遲後落下，**可閃避** | 六杖光牢、五柱鐵貫、九曜縛、闐嵐、冰牙征嵐、卍禁太封、一刀火葬 |
| 瞬發束縛 | 射程內直接命中 | 塞、擊、禁、止繃、白伏、鎖條鎖縛、九十六京火架封滅 |
| 飛行束縛 | 飛向鎖定位置後判定 | 這繩、崩輪、嘴突三閃、百步欄干、百連閂 |
| 擴散環 | 環半徑掃過對手時判定（**跳起來才躲得掉**） | 斬華輪 |

| 特殊 | 各自實作 | 黑棺、千手皎天汰砲、擊界儀、四獸塞門、摑趾追雀、天挺空羅、時間停止 |

#### 特效製作手法（參考動畫表現）

- **粒子**：共用三個 `ParticleSystem`（加算、受重力、煙霧），以 `Emit()` 逐顆發射，避免每個特效各建粒子系統。
- **雷光**：`LineRenderer` 兩層（白色核心＋彩色光暈），每幀重新產生鋸齒折線。
- **黑棺**：五面黑板由遠而近合攏 → 黑色尖錐由棺壁向內貫穿 → 棺槨碎裂成碎片、結算傷害。
- **四獸塞門**：依序出現龍尾（方柱組成的盾）、虎咬（齒輪狀閘門）、龜鎧（六角結晶）、鳳翼（刀刃＋閘閂雙翼），最後傘蓋封頂；期間被封者出不來、攻擊打不出來，但施術者的鬼道打得進去。

#### 互動規則

- **屏障**（`BarrierZone`）：投射物碰到即被擋下；鏡門會**交換施術者與目標**，把投射物反彈回去。
- **追蹤**（摑趾追雀、天挺空羅）：期間施術者的投射物會轉向追蹤、位置鎖定型會跟著目標。
- **反鬼相殺**：銷毀對手所有施放中的效果，並解除自身束縛。
- **雙重詠唱**：下一個攻擊／束縛鬼道延遲 0.45 秒再發動一次。

### 5.8 語音辨識（Vosk 離線）

#### 為什麼不用 Windows 內建聽寫

`DictationRecognizer` 依賴 Windows 的「語音語言」與「線上語音辨識」設定，在使用者電腦上**完全收不到文字**。為了不讓玩家處理系統設定，改用 **Vosk**：模型隨專案附帶（約 70MB），完全離線。

#### 整合步驟

1. 從 NuGet 套件取出 `Vosk.dll`（C# 包裝，放 `Assets/Plugins/Vosk/`）與原生庫 `libvosk.dll`、`libgcc_s_seh-1.dll`、`libstdc++-6.dll`、`libwinpthread-1.dll`（放 `Assets/Plugins/x86_64/`，並以 `.meta` 設定為 Editor＋Win64）。
2. `libvosk.dll` 依賴同資料夾的 MinGW 執行庫，但 Windows 的 DLL 搜尋路徑不含插件資料夾，因此**先用完整路徑依序 `LoadLibrary`**：
   ```csharp
   foreach (var name in new[] { "libwinpthread-1", "libgcc_s_seh-1", "libstdc++-6", "libvosk" })
       LoadLibrary(Path.Combine(Application.dataPath, "Plugins", "x86_64", name + ".dll"));
   ```
3. 模型放 `Assets/StreamingAssets/vosk-model-small-cn-0.22/`，以 `Application.streamingAssetsPath` 讀取。
4. **背景執行緒**：模型載入與 `AcceptWaveform` 都在背景執行緒，主執行緒只負責把麥克風資料放入佇列、取回結果，避免卡頓。

#### 麥克風資料流

```
Microphone（16kHz 環形緩衝）──每幀讀取新樣本──► float→short ──► 佇列 ──► [背景] Vosk
                                                                       │
             主執行緒 ◄── Poll()：完整句子（finals）＋ 暫定文字（partial）◄─┘
```

環形緩衝讀取要處理回捲（分兩段 `GetData`）。

#### 持續監聽的發動時機

1. 逐幀把「已完成句子＋暫定文字」組成目前的詠唱。
2. 判斷正在唸哪一招（見 5.9 的「偵測分數」）。
3. 檢查**招式名是否已在尾端唸出**（尾端文字對招式名的覆蓋率 ≥ 0.72）。
4. 唸完後等辨識穩定 0.3 秒（或 Vosk 回報句子結束）→ 結算、發動、重置辨識器。
5. 停頓 5 秒仍未唸完 → 放棄這段；被擊中 → 打斷（重置）。

### 5.9 詠唱比對與評分

#### 正規化

去除標點空白、全形轉半形、阿拉伯數字轉中文數字（「31」→「三十一」）、簡體轉繁體（只涵蓋詠唱文會用到的字）。

#### 拼音軟性 LCS（本專案的關鍵）

語音辨識的錯誤多半是**同音字**（例：「破道」→「破到」、「縛道」→「婦道」）。若逐字比對，正確發音也會被扣分。因此改為：

1. 每個漢字查表得到所有讀音（不含聲調，支援破音字）。
2. 兩字相似度：
   | 情況 | 分數 |
   |---|---|
   | 同字 | 1.0 |
   | 同音字 | 0.92 |
   | 模糊音（zh/z、ch/c、sh/s、n/l、in/ing、en/eng） | 0.75 |
   | 只有韻母相同 | 0.35 |
3. 以這個分數做**加權 LCS**（動態規劃），取最佳對齊總分：
   ```csharp
   float best = max(dp[i-1, j], dp[i, j-1]);
   float s = Pinyin.Sim(said[i-1], target[j-1]);
   if (s > 0 && dp[i-1, j-1] + s > best) best = dp[i-1, j-1] + s;
   dp[i, j] = best;
   ```
4. 由總分 L 得到：**覆蓋率 recall = L / 目標長度**、**精確率 precision = L / 唸出長度**。

#### 偵測（唸到一半時判斷是哪一招）

```
偵測分數 = max( 0.65 × precision_全文 + 0.35 × recall_全文 ,
               0.98 × (0.5 × precision_招式名 + 0.5 × recall_招式名) )
```

唸到一半時 recall 還很低，所以以 precision 為主；只喊招式名時則由第二項接手。

#### 評分與威力

| 名稱 | 定義 |
|---|---|
| 相似度 | precision（唸的內容有多少是對的） |
| 完整度 | recall（整段詠唱含招式名唸出了多少） |
| 詠唱破棄 | 有詠唱文的鬼道，只唸招式名（招式名分數 × 0.55 > 全文分數） |

```
威力倍率 = (0.25 + 0.85 × 相似度^1.3) × (0.4 + 0.6 × 完整度)
詠唱破棄：× 0.1
完美詠唱（相似度與完整度皆 ≥ 0.9）：× 1.15
最終傷害 = 基礎傷害 × 威力倍率 × 角色鬼道係數
```

評價 S／A／B／C／D 由「相似度 50%＋完整度 50%」決定，詠唱破棄固定為 D。

### 5.10 電腦對手 AI

- 每 0.2～0.55 秒（依難度）重新決策一次，輸出與玩家相同的 `Intent`。
- 決策優先序：被攻擊時防禦 → 玩家詠唱中則瞬步過去打斷 → 對手被束縛時追擊 → 近身連段 → 靈壓全滿時唸奧義 → 中距離唸鬼道 → 遠距離集氣 → 繞圈。
- AI 也會「詠唱」：進入 `Chant` 狀態，詠唱時間依字數計算，畫面右上顯示進度；**被打中就中斷**。命中率、完整度依難度隨機。
- 輔助類鬼道有使用條件（例如體力低於一半才治療、玩家詠唱中才開屏障）。

### 5.11 UI／HUD

全部以 **IMGUI（OnGUI）** 繪製，依 1080p 為基準縮放。為了擺脫「舊遊戲感」：

- **程序化貼圖**：斜角平行四邊形遮罩、光澤漸層、圓角框、九宮格斜角按鈕、放射光芒、光帶。
- **魂魄覺醒風格量表**：斜角體力條（綠→黃→紅漸層、光澤、延遲扣血、低血量閃爍、數值）、四格靈壓條（全滿發光）。
- **3D 頭像**：把角色模型複製到第 30 層、用專屬鏡頭與燈光只拍一次頭部，存成 `RenderTexture`；主鏡頭的 cullingMask 排除第 30 層。
- **詠唱評分特效**：評價字母由大縮小落下＋放射光芒＋數值條跳動＋「完美詠唱／詠唱破棄」印章；角色腳下同時出現對應顏色的光環。
- **語音診斷面板**（F1）：辨識狀態、即時文字、最近辨識、上次評分、各鬼道相似度表。這個面板在開發與教學時非常有用，能直接看到「辨識結果」和「比對結果」分別出了什麼問題。

### 6.3 語音辨識端到端測試（TTS → Vosk → 比對）

用 Windows 中文語音（Hanhan, zh-TW）把詠唱文合成為 16kHz 音檔，送進 Vosk，再計算相似度。比較「逐字比對」與「拼音軟性比對」：

| 詠唱 | Vosk 實際辨識結果（節錄） | 逐字比對 | 拼音比對 |
|---|---|---|---|
| 測試 | 测试 | 0% | **100%** |
| 赤火砲（完整） | 均匀着啊肉的面具万象政治高飞关于人类… 破到之三十一去火炮 | 67% | **85%** |
| 蒼火墜（完整） | …真理与截至仅一找利于不知最的梦壁上破到之三十三舱最 | 48% | **83%** |
| 雷吼炮（完整） | 散步各处的受雇间他经钢铁的车轮… 破到之六十三得后跑 | 45% | **91%** |
| 六杖光牢（完整） | 雷鸣的马车房车的缝隙此物有光群疾病一分为六妇道之六十六涨光牢 | 71% | **95%** |
| 只喊「破道之三十一 赤火砲」 | 破到之三十一至火炮 | 71% | **89%** |
| 只喊「縛道之九 擊」 | 妇道之久即 | 30% | **93%** |

**結論**：小型離線模型的字詞錯誤率不低，但錯誤大多是同音字；以讀音比對可以大幅改善，這是本專案能用「小模型＋離線」達到可玩程度的關鍵。

### 6.4 尚需人工驗證的部分

畫面（Shader、後製、模型外觀）、手感、數值平衡、真人語音（不同口音、環境噪音）都需要在 Unity 中實際遊玩確認。
